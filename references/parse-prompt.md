# 支付凭证解析规范

用在 AUSGLEICH 的截图识别环节。目标是**微信支付/支付宝/银行卡/香港电子钱包的付款凭证截图**，不是小票。

## 输出格式

每张图输出一个 JSON 对象，不要输出多余文字：

```json
{
  "item": "海底捞",
  "date": "2026-09-01",
  "currency": "HKD",
  "amount": 428.00,
  "confidence": 0.95,
  "doubt": ""
}
```

## 字段规则

| 字段 | 怎么取 |
|---|---|
| `item` | 商户名。微信/支付宝优先取"商户全称"，没有就用收款方简称或商品名。去掉"有限公司"之类的后缀 |
| `date` | 支付时间，格式 `YYYY-MM-DD`。只显示"今天/昨天"就按当天/前一天推算，并在 `doubt` 注明 |
| `currency` | 只输出 `CNY` 或 `HKD`。见下方判定 |
| `amount` | **实付金额**，纯数字两位小数。有优惠/折扣取抵扣后的实付，不要取原价 |
| `confidence` | 0–1，你对这次识别的整体把握 |
| `doubt` | 看不清、不确定、需要人看一眼的地方。没问题就空字符串 |

## 币种判定

- `CNY`：`¥`、`CNY`、`人民币`、`元`、人民币符号在数字前
- `HKD`：`HK$`、`$`（香港场景）、`HKD`、`港币`、`港元`
- **美元 `$` 在港币场景极少见**，除非明确写 `USD`，否则香港的 `$` 一律按 HKD
- 跨境支付（微信/支付宝在港消费）看**实付币种**那一行，不是商品标价
- 图上同时有标价和实付两个币种 → 取实付，把汇率信息写进 `doubt`

## 常见版式

- **微信支付「支付成功」页**：顶部大字是金额，下面是商户全称、支付时间、支付方式。金额旁可能有"-"号
- **微信账单列表**：一屏多笔，见下方"一图多笔"
- **支付宝**：顶部金额，商户名在"收款方"或商品标题
- **AlipayHK / PayMe / 八达通**：港币金额常带 `HK$`，日期格式可能是 `DD/MM/YYYY`，注意别把日和月搞反——**看不清就压低 confidence 写进 doubt**
- **银行卡推送通知**：`消费 HKD 428.00`，商户名常缩写

## 必须标注的情况

这些不擅自排除，标出来交给用户判断：

- **转账 / 红包 / 提现 / 充值**：不是消费，`doubt` 写"疑似转账，请确认是否计入"
- **一图多笔**：只取金额最大或最上面的一笔，`doubt` 写"一图含 N 笔，仅取了 XXX，其余未计入"
- **金额看不清**：`confidence` 压到 0.5 以下，`doubt` 写清哪一位看不清
- **日期缺失**：留空 + `doubt` 说明，不要拿今天填空

## 硬规则

- **不确定就压低 confidence，绝不猜数字。** 一个错误的金额会让整轮账对不上，一个空字段只是让人补一下。
- 金额是最重要的字段。图片模糊时宁可整条标低置信度，也不要给一个"看起来像"的数。
- 同一张图不重复识别、不重复计。
